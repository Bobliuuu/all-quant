# UltraQuant on SYCL (Intel GPUs)

Fused multi-token (K-query) FP4/UE8M0 paged decode attention, SYCL port of `uqmt/attn.py` (Triton). Same cache layouts and
semantics: `kc/vc` uint8 `[pages,Hkv,PAGE,D/2]` (low nibble = even element), `ks/vs` UE8M0 `[pages,Hkv,PAGE,D/32]` (value 2^(s-127)),
`q` bf16 `[B,K,Hq,D]`, `block_table` int32, `seq_lens` includes the K spec tokens, query j sees `seq_len-K+j+1` keys,
split-KV (flash-decoding) kernel + reduce kernel, every KV page read once for all K queries x GQA heads.
Rotated K/Q (Hadamard, UltraQuant convention) are consumed as-is: the rotation lives outside the kernel (vector case `rot_h128_b2k4`).

Files: `uq_decode.hpp` (portable kernel + reduce + dispatch), `uq_xmx.hpp` (XMX/joint_matrix path), `test_vectors.cpp`,
`bench.cpp`, `probe.cpp` (device caps / reported joint_matrix shapes), `vectors/` (raw .bin + manifest.txt, generated by
`tools/gen_vectors_sycl.py`, torch CPU), `build.bat` / `build.sh` / `CMakeLists.txt`, `dev/` (box helper scripts), `PRIOR_ART.md`,
`PORTING_LOG.md`.

## Build and run
Open-source DPC++ release (intel/llvm v7.2.0, `sycl_windows.tar.gz`, no admin, user space) plus MSVC for linking on Windows:
```
build.bat test_vectors      & test_vectors.exe vectors --sweep                 # portable path
build.bat test_vectors      & test_vectors.exe vectors --path xmx --sweep      # XMX path
build.bat bench             & bench.exe --path xmx --wg 256 --tn 32 --nsplit sweep --B 2,8 --ctx 4096,16384 --K 1,4,8 --json out.jsonl
```
Linux: `./build.sh test_vectors`. Non-Intel targets: add `-DUQ_NO_XMX` (the joint_matrix path is Intel-only; the portable path is plain SYCL:
sub-group reductions, SLM tiling, `sycl::ext::oneapi::bfloat16`). Device selection via `ONEAPI_DEVICE_SELECTOR`.

## Implementation
- **FP4 dequant**: portable path uses an exact 8-entry value table (`-DUQ_BITTRICK` builds the Triton bf16-bits trick, sign<<15|code3<<6 times 2^126;
  it needs float denormals for code 1 so it is not the default). XMX path never uses float math: bf16 bits are formed by integer ops
  (`0x3F00 + (code3<<6)`, scale folded in as an exponent add of `(s-127)<<7`) or a 256-entry byte->bf16-pair LUT in SLM with a zero mask; exact.
- **XMX path**: joint_matrix bf16 8x16x16 (Xe2/Xe3 report M<=8,N=16,K=16 bf16/fp16, K=32 int8/u8, K=8 tf32; no fp8/fp4 on XMX), fp32
  accumulate. K tile is dequantised into SLM directly in the VNNI layout the B operand needs; S = Q K^T, online softmax (log2 domain),
  P in bf16 (as the Triton kernel), O += P V with O in SLM and rescale by alpha per tile.
- **Split/reduce**: grid = B x Hkv x nsplit work-groups, intermediate `(O/l, lse)` per split, reduce kernel merges with exp2 weights.
  Rows with `seq_len-K+j+1 <= 0` return zeros.

## Correctness (Arc B390, 9 cases x nsplit {1,2,3,8}, 36 runs per path; `results/sycl_arcb390_correctness.log`)
Vectors cover K in {1,2,3,4,8,16}, GQA group 1/4/16, D 64/128, PAGE 16/32/64, ragged seq_lens, shuffled pages, seq_len<K, rotated K/Q, and an upstream-rule case (`paper_rule_b2k4`: vLLM UltraQuant scale rule c=0.156, zero-sentinel scale byte 0, rotated).
Output is bf16, so errors are dominated by output rounding. Criterion: abs err <= 1e-3 + 2^-7*|ref| (1 bf16 ulp) (+6e-3 absolute for the XMX path whose P is bf16).
Both paths: 36/36 pass, worst max_abs_err 7.7e-3 (a short-sequence row with |ref|~2, i.e. a bf16 ulp / cancellation case); typical max_abs_err 1.0-2.5e-3
(raw max abs err under 1e-3 is not reachable with bf16 output when |out|>0.25). Portable path with fp32 P is within 1 bf16 ulp everywhere.

## Compatibility with upstream vLLM UltraQuant
Layout/semantics are the `uqmt` layout (SoA pages, low nibble = even, UE8M0, byte 0 = 0.0 happens to decode to exactly zero via the bit
construction `s<<23`). `cuda/UPSTREAM_COMPAT.md` (cuda-agent) verified upstream's Triton quantiser/store bit-for-bit against
`uqmt.quant` with `rule="paper", c=0.156` (+ -0 canonicalisation) and that the upstream AoS block layout converts to ours with a byte permute.
The generator's quantiser is bit-identical to `uqmt/attn.py::quantize_fp4` (checked) and also implements the upstream rule; the SYCL kernels
pass both. Not done: running upstream vLLM's own Triton fallback on an Intel GPU, and consuming vectors dumped by upstream's AoS layout directly (needs the permute from that doc).

Honest summary: correct and 8x faster than the portable path with XMX, fused verify is 2.7-3x faster than re-reading KV per query, but at
~10% of memory-bandwidth peak the kernel is still ALU/barrier bound (not memory bound). See tuning notes for the ablation and next steps.
Verifying K=4 tokens costs 1.3x one token (fused) vs 3.5x (K independent).
